## Research findings the tasks rely on

Measured in a scratch copy of the repo (`git archive HEAD` + `npm ci --ignore-scripts` + the pins above) — not in the working tree:

- **Supply chain:** none of the six packages has an install script; `npm audit signatures` → 232 packages with verified registry signatures, 95 with attestations; `npm audit` → 0 vulnerabilities. (`eslint-config-prettier` 10.1.8 is the clean release after the compromised 10.1.6/10.1.7.)
- **Node floor:** intersecting `^22.13.0 || >=24` with every `engines.node` in the resulting lockfile fails only for `@napi-rs/lzma-linux-x64-gnu`, a Linux-only optional binary never installed on Windows.
- **ESLint 10:** `defineConfig` and `includeIgnoreFile` are exported by `eslint/config` (no `@eslint/compat`); config lookup starts at each linted file's directory; `eslint:recommended` gained `no-unassigned-vars`, `no-useless-assignment`, `preserve-caught-error`.
- **Project service:** with `projectService: true`, every file resolves through the solution `tsconfig.json` references. A file included by no tsconfig fails with `Parsing error: … was not found by the project service`, so `eslint.config.mjs` joins `tsconfig.node.json` — where `allowJs`/`checkJs` also type-check it (`tsc -b` exit 0 with it included). `out/` is skipped via `.gitignore`, so built JS never reaches the parser.
- **Preset choice, measured on the current code:** `recommendedTypeChecked` reports only `'_deps' is defined but never used (@typescript-eslint/no-unused-vars)` in `src/main/ipc/ipcHandlers.ts`. `strictTypeChecked` + `stylisticTypeChecked` additionally report `no-confusing-void-expression` on the idiomatic arrow shorthands in `src/main/index.ts:32` and `src/preload/index.ts:16` and `no-empty-function` on the intentionally empty registration point → recommended type-checked preset.
- **Unused code:** `tsconfig.base.json` has `noUnusedLocals`/`noUnusedParameters`; `tsc -b` reports `TS6133` for an unused local and an unused parameter, and honours the `_` prefix. The lint rule would duplicate it and reject `_deps` → the lint rule is off; tsc stays the one authority.
- **React hooks:** 7.1.1 exposes `configs.flat.recommended` (`rules-of-hooks` error, `exhaustive-deps` warn, plus React Compiler rules) without `files` → scoped to `src/renderer/**`.
- **Warnings:** ESLint exits 0 on warnings; an `exhaustive-deps` warning alone gives exit 0 by default and exit 1 with `--max-warnings 0` ("ESLint found too many warnings (maximum: 0)") → `lint` uses `--max-warnings 0` so the future `verify` gate cannot pass with hook warnings.
- **Prettier ↔ ESLint:** `npx eslint-config-prettier src/main/index.ts src/renderer/src/App.tsx` → "No rules that are unnecessary or conflict with Prettier were found."
- **Prettier options:** existing code uses single quotes, semicolons, trailing commas and `(arg) =>`. `--list-different` per `printWidth`: 80 → 5 files, 100 → 3, **110 → only `tsconfig.node.json`** (its 112-char `include` line, rewritten by this task anyway), 120 → 2 (re-joins lines broken today) → `singleQuote: true`, `printWidth: 110`.
- **Prettier scope:** Prettier 3 skips `.gitignore` entries on its own. It would rewrite all 7 Markdown docs (list markers, table padding, the verbatim OpenWhispr JS quotes in ARCHITECTURE.md) and the vendored `.claude/skills` docs → `*.md` goes in `.prettierignore`. `package-lock.json` is formatted by the `json-stringify` parser identically to npm → no ignore needed.
- **Typecheck:** `tsc -b` reports errors from both projects in a single run (`TS2322` in `src/main` and `src/renderer/src` together) and still fails on a repeated run. Warm timings: lint ≈ 4 s, typecheck ≈ 3 s.
- **Install facts for the docs:** `better-sqlite3` 13.0.3 has no install script (N-API prebuilds ship in the tarball); `ffmpeg-static` runs `node install.js` (downloads ffmpeg); Electron comes through the `install-electron` postinstall. Origin remote: `https://github.com/PHI-Partners/OpenWhispr.git`.
- **Line endings:** `core.autocrlf=true`; working-tree files are LF except `CLAUDE.md` (CRLF). Prettier's default `endOfLine: "lf"` only affects files it formats; Markdown is excluded.

| Code quality | ESLint 10 flat config, typescript-eslint 8 (`recommendedTypeChecked`), `eslint-plugin-react-hooks` 7, Prettier 3 | Type-aware rules catch floating and misused promises; Prettier owns formatting and `eslint-config-prettier` switches off conflicting rules |

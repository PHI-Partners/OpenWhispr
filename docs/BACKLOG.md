# Implementation Backlog — Meeting Recorder & Transcriber

Numbered in implementation order; tick a checkbox when its task is done and verified. Scope confirmed 2026-09-17: tray/hotkey/overlay, Vulkan + CPU fallback, native WASAPI helper and signing + auto-update (GitHub Releases) are all mandatory.

## Architecture reference (shared by all tasks)

- **Spec sources:** ARCHITECTURE.md (§1 IPC, §2 audio, §3 whisper, §4 data model, §5 packaging, §6 build order), TECH_STACK.md, UI_COMPONENTS.md, THEME.md. Feature epics 4 → 12 follow ARCHITECTURE §6 strictly sequentially ("do not build these in parallel").
- **Layout (electron-vite, TypeScript everywhere):** `src/main` (Electron main), `src/preload`, `src/shared` (IPC channel names + payload types), `src/renderer` (React; one HTML entry per window), `resources/` (`bin/cpu`, `bin/vulkan`, `bin/windows-system-audio-helper.exe`, `icons/`, helper C source), `scripts/` (Node `.mjs` provisioning/build scripts), `tests/` (`fixtures`, `fakes`, `helpers`, `mocks`, `e2e`).
- **IPC:** `window.api` via `contextBridge`; kebab-case channels; every `ipcMain.handle` registered centrally in `src/main/ipc/ipcHandlers.ts` with injected services; the five v1 methods of ARCHITECTURE §1 keep their exact names/channels; every `on*` subscription returns an unsubscribe function.
- **Audio pipeline:** capture-host renderer (the main window) → one `MediaRecorder` (webm/opus, 1 s timeslice) → sequence-numbered `meeting-audio-chunk` IPC → main → one long-running `ffmpeg-static` process → 16 kHz mono s16le PCM → tee into (a) incremental WAV writer (`<userData>/recordings/*.wav` = the meeting's `audio_path`) and (b) silence-aware chunker → serial transcription queue → whisper-server `/inference` → `transcript-update` event + DB append.
- **System audio strategy** chosen at recording start: Electron loopback (`desktopCapturer` source granted through `session.setDisplayMediaRequestHandler` with `audio: 'loopback'`, captured and mixed in the renderer — Epic 6; permanent fallback), or native WASAPI helper PCM mixed in main (Epic 12; preferred when `probe` succeeds). The legacy `chromeMediaSource: 'desktop'` snippet in ARCHITECTURE §2 is not used: it crashes the renderer on current Electron.
- **Recording state:** one state machine in main (`idle → starting → recording → finalizing → idle | error`) broadcast to all windows on `recording-state-changed`; every trigger (window button, overlay, tray, hotkey) goes through it.
- **whisper-server:** the selected model's path is a parameter to `start(modelPath, opts)`, never a config constant — on a fresh install nothing is selected, so the manager sits in `no-model` and spawns nothing. Otherwise: first free port in 8178–8199, `--model <path> --host 127.0.0.1 --port <port>`, plus `--language auto` for multilingual models (whisper.cpp silently assumes English without it; `.en` models must never get it), readiness and 5 s health check on `GET /health`, restart with backoff, and a no-op-by-signature guard so that changing the model or the GPU flag is the *only* thing that stops and respawns the process. Epic 11 swaps the CPU package for a Vulkan-enabled build (dynamic ggml backends, all CPU variants incl. AVX2 in the same directory) and falls back to CPU by respawning with `--no-gpu`.
- **Speech models:** a ten-entry catalog — `tiny`, `tiny.en`, `base`, `base.en` (the only `recommended`), `small`, `small.en`, `medium`, `medium.en`, `large` = `ggml-large-v3.bin`, `turbo` = `ggml-large-v3-turbo.bin` — held as data in `src/shared/whisperModels.json`, not code. **Nothing is bundled:** the installer ships no weights (10.1.1) and every model is downloaded post-install on an explicit user action into `<userData>\models`, relocated when that path contains spaces or non-ASCII characters, which whisper.cpp cannot open. Each entry pins `expectedSizeBytes` and `sha256` against one pinned Hugging Face revision (`resolve/<revision>/<fileName>`, never `main`, so a re-upload cannot invalidate a hash); a 1.2× free-disk preflight precedes every download, one download runs at a time, resumable from a `.tmp` sibling and atomically renamed on completion. ARCHITECTURE §3 and §5 record the same decision and the reasoning behind reversing the original bundled-`ggml-base.en.bin` plan.
- **Data:** `better-sqlite3`, the single `meetings` table exactly as in ARCHITECTURE §4, schema evolution only through additive `ALTER TABLE … ADD COLUMN` in try/catch; user settings live in a main-owned `<userData>\settings.json` (defaults, atomic write, corrupt-file recovery), read and written only in main and exposed over IPC — never localStorage and never a second SQLite table, so the single-`meetings`-table rule stands.
- **Test seams:** environment overrides read only in `src/main/config.ts` — `OW_USER_DATA_DIR`, `OW_WHISPER_SERVER_CMD`, `OW_AUDIO_HELPER_CMD`, `OW_CHUNK_SECONDS`, `OW_FORCE_CPU`, `OW_DISABLE_SYSTEM_AUDIO`, `OW_DISABLE_UPDATER`, `OW_MODEL_BASE_URL`.
- **Version compatibility (validated 2026-09-17 — re-check through Context7/npm when installing, never blindly take `@latest`):** Electron 44.x; electron-vite 5.x supports Vite ≤ 7 (not 8) with the matching `@vitejs/plugin-react` 5.x; Vitest 5 (`test.projects`); `better-sqlite3` ≥ 13 ships an N-API prebuild that loads in both Node and Electron (no native rebuild); electron-builder 26.x key names (`win.signtoolOptions`, `forceCodeSigning`); whisper.cpp Windows binaries live on `bNNNN` release tags and there is no official Vulkan build.
- **Definition of done for every task:** tests written first (TDD) with the Epic 2 harness; `npm run verify` green; real-binary smoke run when the task touches real binaries; library APIs checked through Context7; app-level behaviour verified with Playwright (per `CLAUDE.md`).
